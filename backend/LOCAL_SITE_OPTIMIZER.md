# Local Site Optimizer

`LocalSiteOptimizationRequest` and `optimize_local` in app.optimization implement same-time neighbourhood exploration. The public job wrapper supplies server resource policy and a scientific evaluator; all operation decisions and scores come from existing Command 08. Only candidate coordinates and their actual DEM heights change. UTC, duration, explicit requirements, observer heights, correction, thresholds and temporal policy remain fixed. Named inputs must first resolve to coordinates; this prototype accepts coordinate inputs only.

Generation uses pyproj.Geod on the 1737400 m lunar sphere, planetocentric/east-positive MOON_ME_DE421. Stratified bounded radial rings cover up to 5000 m; the baseline is separate. A reserved bounded refinement probes eight bearings around the two best coarse screening regions. Candidates outside confinement are rejected and coordinates are deterministically deduplicated. Counts and scope are finite; this is not exhaustive raster-cell search.

Screening uses existing MultiResolutionDem policy/coverage/quality/conflict evidence. Associated validated slope products are absent in the configured asset directory, so a bounded unmasked 3×3 elevation window estimates the central grid gradient using real pixel spacing. Missing neighbours yield UNKNOWN. The grid-gradient approximation is not certified local physical slope, and 5/80 m sampling cannot resolve rocks or small craters. The default 10-degree screen is EXAMPLE_OPERATION_ASSUMPTION. UNKNOWN or failed slope does not pass. Screening query positions are resource-admitted before reads.

Selected candidates run the existing observer/SPICE/exact horizon/disk/windows/operation chain, with candidate-specific window SHA. Baseline is included in the detailed limit. Source metadata must match for score comparison; only completely evaluated MET candidates improving operation status/score become recommendations. Slope screening is separate from the Planning Suitability Index. High NOT_MET scores do not become eligible. A no-better-site outcome applies only to evaluated sites.

Results expose geodesic distance/bearing (north=0°, east=90°), selected DEM height/resolution/hash, slope method, quality, operation result, metrics, evidence identity and limits. Unselected candidates remain NOT_EVALUATED_RESOURCE_LIMIT, not NOT_MET. Jobs keep partial evidence and exact-source checkpoints. Source defaults remain Site01 5 m + Product90 80 m; LROC/20 m are not silently enabled.

Command 10 closure adds optional TERRAIN_DIVERSE admission. It first considers quality-layer completeness and source resolution, then uses geodesic separation to avoid spending all detailed slots in one low-slope cluster. SLOPE_ONLY remains default. Neither ordering is the planning score or proof of favorable illumination. Detailed windows, requirements and the existing v1 score remain authoritative.
